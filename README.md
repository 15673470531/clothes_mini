# clothes 小程序（前端）

衣服 + 搭配的记录工具。原生 JS + WXSS（不用官方 TS + Less 模板，与手上其他小程序写法统一）。

## 一、当前状态

静态稿（一期前端），数据走本地存储 + mock 填充，**没有后端**。

## 二、结构

```
app.js / app.json / app.wxss     全局：设计 token、tabBar 配置
custom-tab-bar/                  自研底导：衣橱 / 穿搭 / 我的（纯文字，图标待定）
utils/mock.js                    品类/颜色/季节/场合常量 + mock 衣物与搭配
utils/store.js                   本地数据层（二期换接口只改这里，页面不动）
pages/wardrobe/                  衣橱：概览 + 品类筛选 + 列表（tab 0）
pages/outfit/                    穿搭：我的搭配卡片列表（tab 1）
pages/outfit-edit/               新建搭配：从衣橱多选衣物
pages/item-edit/                 记录/编辑衣物：品类 → 颜色 → 季节场合，照片可选
pages/mine/                      我的：昵称头像 / 联系客服 / 意见反馈 / 关于应用 / 退出登录（tab 3）
pages/service/                   联系客服：微信客服会话 + 微信号/邮箱复制（联系方式在 service.js 顶部）

                                 （从「我的」页「关于应用」进；样式 2026-09 优化过：
                                  封面浅紫底、分块标题带紫竖线、块内条目有细分隔线）
pages/feedback/                  意见反馈：提交给后端
```

## 三、几个关键设计决定

1 **衣物没有照片也能用**：列表和搭配卡片在无图时用品类图标 + 颜色色块表示，
   搭配页因此不依赖照片，没录图的用户打开不是空白。
2 **录入流程：先照片，后信息**（用户指定，2026-09 曾试「只有品类必填」的无压力版，被要求撤回）——
   点「＋」弹「拍照 / 从相册选择」；**相册可一次选多张（最多 9 张，2026-09 加）**，
   选完的照片逐张压缩落盘、进「待录入队列」（存 storage），录入页**并排一行缩略图**：
   默认停在第一张没录的，**点哪张填哪张**（已录的压暗打勾、点了只提示不切），
   每张各自一份表单快照（填一半切走再切回来不丢）。存完一张自动跳下一张没录的，全录完回衣橱。
   中途退出不丢：队列留本机，下次点「＋」问「还有 N 张没录完，继续 / 丢掉」。
   一批还剩别的没录时，录入页多一行「剩下 N 张都用这套属性」——勾上点保存，
   当前这件 + 其余没录的**一次请求生成 N 条**（名称自动加序号「白T 2 / 白T 3」）。
   **必填只有两项：照片、品类**；其余全部给默认值——颜色可不选（空着时列表与搭配卡片用中性灰块
   `#E9ECF1` 呈现，**不会显示成黑色**）、季节按当前月份预选、场合默认「休闲」、名称留空则显示品类名。
   编辑已有衣物时照片可换可不换。
   另有「保存并再记一件」（保存后清照片/品类/颜色/名称，季节与场合回到默认值，并立刻让选下一张照片；
   一批多张时这个按钮不显示，因为保存会自动跳到下一张没录的）。
3 **不做统计页**（按用户要求整页砍掉，也没有塞进别的页面）。
   记录衣物页的可见区块顺序：照片（必填）→ 品类（必填）→ 季节（按月份默认）→ 名称（可不填）
   → **更多属性（默认折叠，内含颜色 + 场合）**；折叠行右侧显示已选摘要（如「黑/白 · 休闲」，
   未填时显示「未填」），不展开也能看到里面有什么。编辑已有衣物且填过这两项时自动展开。
4 **删衣物会检查搭配引用**：被 N 个搭配用着时弹窗告知是哪几个，用户确认才删，
   不静默产生悬挂引用；搭配卡片上对已删衣物显示「有 N 件已从衣橱删除」。
5 **照片存本地需落盘**：`wx.chooseMedia` 的临时路径重启后失效，已用
   `FileSystemManager.saveFile` 存到用户目录。注意本地用户文件目录有容量上限，
   一件一张压缩图约 100-200KB，**上限内大约只放得下 50-80 件**，件数多要上后端（二期）。
   → **二期已做（2026-09）**：照片改**异步上传**——保存时只提交记录（秒回），照片由
   `cloud.flushUploads()` 后台上传 OSS，传成功后清掉本机文件，所以本机不再长期堆图
   （本机文件只在「还没传上去」那段时间存在）；上传前会再压一道质量（`utils/photo.js`）。
   **衣橱格子和穿搭卡片右下角点一个小圆点**（`cloud.photoBadge` / `coverBadge`，三态互斥、
   只给颜色不写字）：灰 = 本机有图、云端还没地址；绿 = 已进对象存储；黄 = 已上传但落在
   服务器本地盘。按后端出的 `imageStorage` / `coverStorage` 字段区分（老接口不返回该字段时
   前端按 URL 里有没有 `/storage/` 兜底判；没配 OSS 的后端就是落本地盘、地址是 `域名/storage/...`）。
   这四个颜色各是什么意思，在「我的 → 关于应用 → 数据与账号 → 照片存在哪」有图例说明
   （图例里的点和衣橱里那颗用同一套尺寸/白圈/阴影，用户能对上号）。
6 已知取舍：录入中途放弃（不保存就返回）时，已经落盘的那张照片不会自动清理，
   会白占本地存储。二期可加「清理无引用的图片文件」逻辑。
7 **记录衣物页排版（2026-09 优化，方案甲「分组卡片化」）**：
   攒成**三张卡**——卡一 = 照片行 + 分割线 + 品类；卡二 = 季节 + 分割线 + 名称行；卡三 = 更多属性（折叠）。
   选项一律**等宽格**（`.grid` + `.cell` + `.col3` / `.row5`），不再用小胶囊：
   品类 3 列 × 2 行、季节 4 格一行、场合 5 格一行——**等宽是为了杜绝某种选项单个字导致的参差**
   （场合 5 项按 4 列排会剩 1 个单开一行，所以走单行等宽）。
   大标题减成 12rpx 灰字小标签（`.label`），卡内分段用 `.divider`；
   卡片阴影从 `rgba(28,50,110,.06)` 加深到 `.10`、新增 `--fill` 作格子底色；
   底部「保存并再记一件」缩成「再记一件」+ 主按钮「保存」，主次分明。
   颜色保留 6 列等宽、圆点 64rpx。整页折叠态约 825px（720px 屏需滚约 105px）。
